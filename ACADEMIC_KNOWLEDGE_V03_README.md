# Academic Knowledge Model v0.3 — parallel prototype

This implementation preserves the human Gold Standard v0.1 as a working baseline and models five assessment parts from the prior Q2/Q4 discussion. It does not import or run v0.1/v0.2, execute promotion, verify the original PDFs, or produce student mastery estimates.

## Contents and current result

- `academic_knowledge_schema_v03.py`: strict Pydantic entities and local value constraints.
- `validate_academic_knowledge_v03.py`: reference, provenance, review, curriculum exclusion and source-readiness checks; read-only CLI.
- `build_academic_knowledge_v03_prototype.py`: deterministic builder; writes only `output/academic_knowledge_v03/prototype.json` and `validation_report.json`.
- `test_academic_knowledge_v03.py`: 62 behavior/failure-path tests, including preservation checks against the pinned manifest.
- `output/academic_knowledge_v03/stable_baseline_sha256.json`: pre-implementation hashes; never regenerated by the builder.

Current artifact: 15 competencies; 14 concepts; 34 Gold Standard entries; 2 questions; 5 assessable parts plus the Q4(c) container; 6 part–competency mappings; 4 task conditions; 6 explicit condition attachments; one LDS resource used by two parts; 22 evidence annotations.

Gold competency dispositions remain **9 approved / 3 strong_candidate / 3 candidate**. All canonical registry statuses are **draft**, and all new reviewable records are **pending**. The two deferred baseline entries remain separate from concepts and curriculum exclusions.

`structure_valid = true`; `source_verified = false`. This is the expected honest result. Source labels for the specification, paper and mark scheme come from the inherited discussion; original files, exact pages and wording have not been verified. Evidence is explicitly inherited paraphrase, not quotation. The observations do not acquire official authority merely by referring to an official source label.

There are no fabricated objective IDs, actual curriculum scopes, difficulty measurements or review decisions in the real working artifact. Preserved scope notes are unbound Gold Standard entries until official locators are registered. Scope/objective/exclusion mechanisms are exercised using disposable test fixtures, not fabricated official content in the saved prototype.

## Run from the project root

```powershell
& .\.venv\Scripts\python.exe -B build_academic_knowledge_v03_prototype.py
& .\.venv\Scripts\python.exe -B validate_academic_knowledge_v03.py
& .\.venv\Scripts\python.exe -B -m unittest test_academic_knowledge_v02 test_academic_knowledge_v03
```

The builder may overwrite its two own v0.3 outputs deterministically; it does not touch legacy outputs. `-B` suppresses bytecode cache writes.

The validator exits 0 for structural success, 1 for invalid structure or missing/unreadable input, and 2 when `--require-source-verified` is requested but the selected mapping set lacks verified material. The current artifact should exit 2 under that stricter flag. An empty selection is never reported as source-verified.

## Trust boundary and review

`validate_document(data, trust=ExternalTrust(...))` accepts a caller-owned verification registry. The CLI uses an empty registry and provides no flag to trust a file supplied alongside the model. This prevents self-declared JSON approvals or verification flags from becoming authoritative.

The API assumes its caller controls the trust registry. It is an integration boundary, not an authentication, digital signature, or production approval service. A trusted application must populate it from independently reviewed records; passing attacker-provided data into this argument would defeat that boundary. This prototype does not implement the operator workflow for registering actual PDFs or human identities.

- `SourceVerification` binds the normalized SourceDocument record, independently selected artifact path and byte hash. Only that trusted path is read; payload paths are never opened before trust matching.
- `LocatorVerification` binds the normalized locator and source bytes, plus checked text when quotations are needed. A file hash alone is not a locator/content check.
- Review decisions must match an external exact decision digest. `review_content_digest(data, target)` binds the target and its cited evidence, locators and sources. Changing an evidence annotation under the same ID invalidates the review.
- Normalize records through the schema before computing trust digests so default fields are included. The test helper demonstrates this only on disposable, explicitly test-only text files; those tests are not Pearson verification.
- Source readiness and human approval are separate. Source-verified material does not promote a competency or approve its interpretation. Gold Standard dispositions never authorize promotion.

## Minimal refinements made during implementation

1. Scope exclusions have an `exclusion_id` and a typed review target so they can be approved independently of the containing scope.
2. Source locators may carry `assessment_question_id` as well as `assessment_part_id`; this rejects incorrect question-level evidence on shared conditions.
3. Review digests include the cited evidence and source locations, rather than only mutable reference IDs.
4. Nested action classifications are optional and have their own review target using the competency ID. No hierarchy edges are implemented, and no classification has been invented in the working dataset.

These refinements make the proposed validation rules concrete without expanding the academic scope. v0.2 files and its semantics remain unchanged.

## Intentionally outside this prototype

No automatic v0.2 adapter or production migration; no merge of the separate teaching demo; no PDF ingestion or real source verification; no new human approvals; no full question-bank coverage; no mark allocation across skills; no prerequisite hierarchy, learning requirements, mastery criteria, student mastery or calibrated difficulty model.

The next academic step is to register and verify the original specification, question paper and mark scheme locations, then review each proposed relation. It is not to treat a structural test pass as curriculum truth.
